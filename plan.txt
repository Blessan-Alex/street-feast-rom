Below is a focused, senior-level implementation plan, phase by phase, aligned with the issues and the production-grade guidance in `help.txt`. Each phase includes goals, concrete steps, ownership hints (client vs backend), and acceptance criteria.

---

## Phase 0 — Safety Net: Navigation Arg Contract
**Goal:** Stop losing order context (table, license, orderId, mode).

- Add `OrderNavArgs.kt` (data class + `from(bundle)` + `toBundle()`).
- Fields: `orderType`, `tableNumber`, `licensePlate`, `showHeader`, `existingOrderId`, `isEditing`, `chefTip`, `orderId`.
- Refactor all fragments that navigate in the order flow (`OrderType`, `OrderWhere`, `OrderItem`, `PreviewOrder`, `PreviewOrderHeader`, `ItemCustomize`) to read/write args only via `OrderNavArgs`.
- Update nav actions to pass `args.toBundle()`.

**Acceptance:** No fragment in the order flow accesses raw bundle keys; navigating back and forth preserves table/license/edit flags.

---

## Phase 1 — EatAway License Propagation (High Impact)
**Goal:** Eat Away orders place successfully with 4-digit license.

- In `OrderWhereFragment`: include `licensePlate` when navigating for EatAway.
- In `OrderItemFragment`: read `licensePlate` from args; pass it onward to preview/header.
- In `PreviewOrderFragment`: show license, require exactly 4 digits, disable Place Order until valid.

**Acceptance:** Entering 4 digits once is enough; no “need 4 digit license number” error on place order.

---

## Phase 2 — Table Selection UI (Reachable on Small Screens)
**Goal:** All table buttons reachable; future-proof for dynamic counts.

- Minimal option: wrap content (appbar→bottom nav) in `NestedScrollView` with `clipToPadding=false`; ensure bottom padding so row 7 isn’t cut.
- Better option: RecyclerView grid (span=2) bound to a list (initially 1..7); reuse occupied state styling.
- Keep occupied state logic; keep selection behavior.

**Acceptance:** On smallest screen and large font, table 7 is selectable (scroll if needed).

---

## Phase 3 — Given Orders Table Display Sanitization
**Goal:** No bogus table numbers (40/41) shown; non–dine-in labeled correctly.

- Add `TableDisplayMapper.kt`: for DineIn enforce 1..7 else “Table ?”/hidden; for EatAway show `EatAway ####`; for Parcel show “Parcel”.
- Update `GivenOrderFragment` to build chips using mapper; dedupe by `orderId` (not raw table number).

**Acceptance:** Chips never show >7; EatAway/Parcel render meaningful labels.

---

## Phase 4 — Add-Items/Edit “Table Occupied” Fix
**Goal:** Editing/adding items to an existing DineIn order must not be blocked by occupancy.

- Backend (preferred): In `orders_upsert` or a new RPC, skip table-availability check when `parent_order_id` is set or `isEdit=true`.
- Frontend: stop creating child DineIn orders for add-items. Instead, either:
  - Use an `append_items_to_order(order_id, items[])` RPC, or
  - Merge and call `alter_order` on the same orderId, or
  - Use `update_order_item` for qty/size changes and `delete_order_item` for removals.
- Keep table locked to the parent’s table; do not revalidate occupancy for edits/adds.

**Acceptance:** Add-items/edit flows succeed for occupied tables; no duplicate child orders; orderId stays the same.

---

## Phase 5 — Notification Sound (3–5s, Reliable)
**Goal:** Consistent audible cue in foreground/background.

- Add `res/raw/ping_long.wav` (3–5s) or loop existing ping for up to 5s with a timed stop.
- Set channel sound in `NotificationHelper.createNotificationChannel` with `setSound(uri, audioAttributes)`; create channel once.
- Foreground: if still using `SoundManager`, add try/catch, optional looping with delayed stop.

**Acceptance:** Background notifications play the long sound via channel; foreground play is stable (no crashes, no infinite loop).

---

## Phase 6 — Crash Hardening (Realtime + Navigation)
**Goal:** Chef/waiter apps don’t crash when the other updates.

- Realtime callbacks: wrap with lifecycle guards (`isAdded`, `view != null`, `STARTED`); post UI work to main.
- Add `navigateSafe` helper for NavController; use it for notification clicks and realtime-triggered navigation.
- Add null/detached checks before accessing adapters/bindings inside callbacks.

**Acceptance:** No crashes when notifications or realtime events arrive mid-navigation or after fragment detach.

---

## Phase 7 — Login Persistence
**Goal:** Stay logged in after back press or process death.

- Supabase client: enable persistent storage + auto refresh (`Auth` config with storage adapter) and load session on startup before routing.
- Do not clear ServiceLocator/auth on back press; only on explicit logout.
- Keep back press just finishing the activity.

**Acceptance:** Kill app or press back and reopen → still logged in; logout still works and clears session.

---
