You’re in a **navigation ping-pong loop** caused by **more than one place doing “auth/role routing”**.

### What your log proves (the loop)

1. **LoginActivity** says: `isAuthenticated changed to: true` → **Navigating to MainActivity**
2. **ChefPageActivity** opens (role CHEF)
3. Then **MainActivity opens again** while you’re already in Chef:
   `ApplicationService.onActivityCreated: MainActivity@...`
4. MainActivity says: `routing to role-specific activity` → launches **ChefPageActivity again**
5. ChefPageActivity gets destroyed/created repeatedly → looks like “chef page ↔ login/main loop”.

So the core issue is: **LoginActivity always goes to MainActivity**, and **MainActivity also routes to Chef**, and/or **ChefPageActivity sends you back to MainActivity/Login** on a guard. Multiple routers = infinite loop.

---

## Fix (clean architecture): ONLY ONE router in the whole app

Create a single **AuthGateActivity (Router)** and make it the **only** place that decides:

* Not logged in → LoginActivity
* Logged in + role=CHEF → ChefPageActivity
* Logged in + role=WAITER → Waiter/MainActivity

Then **remove role-routing from LoginActivity/MainActivity/ChefPageActivity** (they should only show UI, and only send you to Login on logout/expired session).

---

## 1) AuthGateActivity (Launcher + only router)

**Manifest**

```xml
<activity
    android:name=".activities.AuthGateActivity"
    android:exported="true">
    <intent-filter>
        <action android:name="android.intent.action.MAIN"/>
        <category android:name="android.intent.category.LAUNCHER"/>
    </intent-filter>
</activity>

<activity android:name=".activities.LoginActivity" android:exported="false"/>
<activity android:name=".activities.MainActivity" android:exported="false"/>
<activity android:name=".activities.ChefPageActivity" android:exported="false"/>
```

**AuthGateActivity.kt**

```kotlin
class AuthGateActivity : AppCompatActivity() {

    private var routed = false

    override fun onCreate(savedInstanceState: Bundle?) {
        super.onCreate(savedInstanceState)

        lifecycleScope.launch {
            // IMPORTANT: avoid routing twice (config change / multiple emissions)
            if (routed) return@launch
            routed = true

            val session = authRepo.currentSession() // supabase session
            if (session == null) {
                openAndClear(LoginActivity::class.java)
                return@launch
            }

            val userId = session.user.id
            val roleRaw = authRepo.fetchUserRole(userId) // from users table
            val role = roleRaw.trim().uppercase() // normalize "chef" vs "CHEF"

            when (role) {
                "CHEF" -> openAndClear(ChefPageActivity::class.java)
                "WAITER" -> openAndClear(MainActivity::class.java)
                else -> openAndClear(LoginActivity::class.java) // or a RoleSelect screen
            }
        }
    }

    private fun openAndClear(target: Class<*>) {
        startActivity(Intent(this, target).apply {
            flags = Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK
        })
        finish()
    }
}
```

## 2) LoginActivity: DO NOT open MainActivity directly anymore

After login success, just go to the router:

```kotlin
private fun onLoginSuccess() {
    startActivity(Intent(this, AuthGateActivity::class.java).apply {
        flags = Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK
    })
    finish()
}
```

✅ This prevents “Login → Main → Chef → Main → Chef …”

---

## 3) MainActivity & ChefPageActivity: remove any “routeToRole” logic

They should **never** decide where to go **if logged in**.
They should only do this:

* If session becomes null (logout/expired) → go Login (clear task)

Example guard (same for both activities):

```kotlin
override fun onStart() {
    super.onStart()
    if (authRepo.currentSession() == null) {
        startActivity(Intent(this, LoginActivity::class.java).apply {
            flags = Intent.FLAG_ACTIVITY_NEW_TASK or Intent.FLAG_ACTIVITY_CLEAR_TASK
        })
        finish()
    }
}
```

🚫 Don’t do: “if logged in → go MainActivity” inside ChefPageActivity.
That’s exactly what creates the ping-pong.

---

## 4) One more likely bug: role casing mismatch

Your log shows:
`Found user - role: chef` (lowercase)

If you compare against `"CHEF"` without normalization, some screens may think role is invalid and kick to Login/Main. Always normalize:

```kotlin
val role = dbRole.trim().uppercase()
```
