Key line:

```text
java.lang.NullPointerException
    at com.streatfeast.app.fragments.ChefNewOrdersFragment.getBinding(ChefNewOrdersFragment.kt:22)
    at com.streatfeast.app.fragments.ChefNewOrdersFragment.observeOrders$lambda$0$2(ChefNewOrdersFragment.kt:90)
    ...
    at androidx.recyclerview.widget.AsyncListDiffer.onCurrentListChanged(AsyncListDiffer.java:379)
```

So:

* The crash happens **after Accept**.
* `OrdersViewModel` refreshes → `newOrders` changes → `adapter.submitList(...)` runs.
* The **`submitList` completion callback** is executed **after** the Fragment’s view is destroyed (because we navigated to the Preparing screen).
* At that moment `_binding == null`, but your `binding` getter (`_binding!!`) is still used inside the callback → 💥 NPE.

Specifically, this bit is the problem:

```kotlin
adapter.submitList(sorted) {
    if (sorted.isNotEmpty()) {
        binding.rvNewOrders.scrollToPosition(0)  // <- uses binding after onDestroyView
    }
}
```

`AsyncListDiffer` posts this callback on the main thread, so it can easily fire *just after* `onDestroyView()`.

---

## ✅ Fix: Don’t touch `binding` inside the `submitList` callback

Two safe options; I’ll give you the **robust version** that also protects `observeOrders` from running when `binding` is null.

### 1. Update `observeOrders()` in `ChefNewOrdersFragment`

Replace your `observeOrders()` with this:

```kotlin
private fun observeOrders() {
    viewModel.newOrders.observe(viewLifecycleOwner) { orders ->
        // View might already be destroyed when this arrives
        val currentBinding = _binding ?: run {
            android.util.Log.w(
                "ChefNewOrdersFragment",
                "observeOrders called after view destroyed, ignoring update"
            )
            return@observe
        }

        android.util.Log.d("ChefNewOrdersFragment", "newOrders changed, size=${orders.size}")

        val sorted = orders.sortedWith(
            compareByDescending<com.streatfeast.app.models.Order> {
                it.orderNumber.takeIf { num -> num > 0 } ?: Int.MIN_VALUE
            }.thenByDescending {
                it.createdAt
            }
        )

        // Capture the RecyclerView BEFORE submitList schedules its diff callback
        val recyclerView = currentBinding.rvNewOrders

        adapter.submitList(sorted) {
            if (sorted.isNotEmpty()) {
                // Use the captured view, not binding
                recyclerView.scrollToPosition(0)
            }
        }

        // Show/hide empty state using the safe binding reference
        if (sorted.isEmpty()) {
            currentBinding.emptyState.visibility = View.VISIBLE
            currentBinding.rvNewOrders.visibility = View.GONE
        } else {
            currentBinding.emptyState.visibility = View.GONE
            currentBinding.rvNewOrders.visibility = View.VISIBLE
        }
    }
}
```

What changed:

* We **never** call the `binding` getter directly inside the observer.
* We early-return if `_binding` is already null (view destroyed).
* We **capture** `currentBinding` and `recyclerView` *before* `submitList` posts its callback.
* The callback now only uses local `recyclerView`, so it doesn’t care if `_binding` later becomes null.

### 2. (Optional) Mirror the same pattern in `ChefPreparingFragment`

Your preparing list also uses `submitList`. To avoid the same crash there when you navigate away, use the same pattern:

```kotlin
private fun observeOrders() {
```
