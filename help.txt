Small improvements / clarifications

You don’t have to change the whole plan, just tweak mental notes:

Realtime and OneSignal are independent paths

You correctly separate them in testing, but it’s worth stating explicitly:

Supabase Realtime → local notifications + UI updates.

Edge Function + OneSignal → remote push (works even when app is killed / offline).

So if OneSignal pushes don’t work, Realtime is not the cause (it’s just a separate bug that you also have).

Naming: “player id” vs “subscription id”

Your plan says:

Confirm it stores subscription ID in users.onesignal_player_id

I’d strongly recommend renaming the DB column to something like onesignal_subscription_id (or add a new column, deprecate the old one), just so you never confuse:

old v4 player_id (user-level id)

v5 subscription id (per-device/channel id)

Your Android code is clearly sending sub.id which is the subscription ID, not the OneSignal user id.

Edge Function + OneSignal v5

The key change you already mentioned is spot on:

Use include_subscription_ids: [ "1a5a944e-..." ]
instead of include_player_ids.

You can keep using the POST /notifications endpoint from the REST API; the main thing is which ID type you use in the payload.
