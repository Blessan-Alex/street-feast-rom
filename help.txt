## 1. Backend: send a OneSignal push on every new order

In your `order-events` Edge Function, once you’ve parsed the webhook payload, you need to:

* Figure out **which subscription ID(s)** to send to (you already store them via `registerDevice(subscriptionId)`).
* Call OneSignal’s `/notifications` endpoint with `include_subscription_ids`.

Example (Deno / TypeScript):

```ts
import { serve } from "https://deno.land/std/http/server.ts";

const ONESIGNAL_APP_ID = Deno.env.get("ONESIGNAL_APP_ID")!;
const ONESIGNAL_REST_KEY = Deno.env.get("ONESIGNAL_REST_KEY")!;

async function sendNewOrderPush(subscriptionId: string, orderNumber: number, orderId: string) {
  const body = {
    app_id: ONESIGNAL_APP_ID,
    include_subscription_ids: [subscriptionId],        // v5 style
    headings: { en: `New order #${orderNumber}` },
    contents: { en: `Order #${orderNumber} just came in` },
    data: {
      orderId,
      number: orderNumber,
    },
    android_channel_id: "orders_channel",             // must match your Android channel id
    android_sound: "order_ping",                      // optional, custom sound name (see below)
  };

  const res = await fetch("https://onesignal.com/api/v1/notifications", {
    method: "POST",
    headers: {
      "Authorization": `Basic ${ONESIGNAL_REST_KEY}`,
      "Content-Type": "application/json",
    },
    body: JSON.stringify(body),
  });

  if (!res.ok) {
    const text = await res.text();
    console.error("OneSignal error:", res.status, text);
    throw new Error(`OneSignal error: ${res.status}`);
  }
}

serve(async (req) => {
  try {
    const payload = await req.json();
    const { type, table, record } = payload;

    if (table === "orders" && type === "INSERT") {
      const order = record;
      const orderId = order.id as string;
      const orderNumber = order.order_number as number;

      // TODO: lookup subscriptionId(s) for the chef(s) for this store
      // e.g. select onesignal_subscription_id from users where store_id = order.store_id AND role = 'chef'
      const subscriptionId = "1a5a944e-a5df-405f-9a4f-abad5283c026"; // example, from DB

      await sendNewOrderPush(subscriptionId, orderNumber, orderId);
    }

    return new Response("OK", { status: 200 });
  } catch (e) {
    console.error("order-events error:", e);
    return new Response("Error", { status: 500 });
  }
});
```

Once this is wired:

* Even if the app is in the **background or killed**, FCM + OneSignal will show a system notification.

Your existing `MainActivity.setupOneSignalNotificationHandler()` will handle **clicks** on that notification and navigate to the `chefNewOrdersFragment`.

## 2. Android: make the notification play a sound (“ring”)

There are two pieces:

### 2.1. Create a channel with sound (used by both OneSignal and local notifications)

1. Add a sound file in your app:

* Place `order_ping.mp3` (or `.wav`) under:
  `app/src/main/res/raw/order_ping.mp3`

2. Update `NotificationHelper.createNotificationChannel` to assign that sound:

```kotlin
fun createNotificationChannel(context: Context) {
    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
        val channel = NotificationChannel(
            Constants.NOTIFICATION_CHANNEL_ID,           // e.g. "orders_channel"
            Constants.NOTIFICATION_CHANNEL_NAME,         // e.g. "Orders"
            NotificationManager.IMPORTANCE_HIGH
        ).apply {
            description = context.getString(R.string.notif_channel_orders)
            enableVibration(true)

            // Set custom sound
            val soundUri = Uri.parse(
                "${ContentResolver.SCHEME_ANDROID_RESOURCE}://${context.packageName}/${R.raw.order_ping}"
            )
            val audioAttrs = AudioAttributes.Builder()
                .setUsage(AudioAttributes.USAGE_NOTIFICATION)
                .setContentType(AudioAttributes.CONTENT_TYPE_SONIFICATION)
                .build()
            setSound(soundUri, audioAttrs)
        }

        val notificationManager =
            context.getSystemService(Context.NOTIFICATION_SERVICE) as NotificationManager
        notificationManager.createNotificationChannel(channel)
    }
}
```

3. Make sure `Constants.NOTIFICATION_CHANNEL_ID` matches the one you use in:

* `NotificationHelper` (already does)
* The OneSignal payload: `android_channel_id: "orders_channel"` (or whatever the ID is)

Now:

* Any notification posted to that channel (local or from OneSignal) will play `order_ping`.

You can even remove the manual `SoundManager.playSound(...)` if you like and rely solely on channel sound.

### 2.2. Make OneSignal use that channel

In the OneSignal notification payload (Edge Function), you already saw:

```ts
android_channel_id: "orders_channel",
android_sound: "order_ping",
```

* `android_channel_id` → must exactly equal `Constants.NOTIFICATION_CHANNEL_ID`.
* `android_sound` is optional: for Android 8+ the **channel’s** sound is what really matters. You can keep it for older devices.

  * Supabase → webhook → Edge Function → OneSignal

## 1. Actually show a local notification when a new order arrives

From the logs:

```text
SupabaseOrderRepository  D  Realtime INSERT: {...}
SupabaseOrderRepository  D  New order detected...
SupabaseOrderRepository  D  Invoking 2 registered callbacks
OrdersViewModel          D  New order callback invoked...
Toast                    V  show: caller = ...ChefNewOrdersFragment.observeNewOrders...
```

There’s **no call to `NotificationHelper`** here.

You need to call `NotificationHelper.showNewOrderNotification(...)` at the point where you already know “new order arrived”.

A good place is inside `SupabaseOrderRepository` where you log *“New order detected”*.

Example (pseudo-code, adapt to your actual repo):

```kotlin
class SupabaseOrderRepository(
    private val appContext: Context,
    // ...
) {
    private val applicationContext = appContext.applicationContext

    private val callbacks = mutableListOf<(String, Int?) -> Unit>()

    private fun handleRealtimeInsert(payload: JsonObject) {
        Log.d("SupabaseOrderRepository", "Realtime INSERT: $payload")

        val orderId = payload["id"]?.jsonPrimitive?.content ?: return
        val orderNumber = payload["number"]?.jsonPrimitive?.intOrNull

        Log.d("SupabaseOrderRepository", "New order detected: id=$orderId, number=$orderNumber")

        // 🔔 LOCAL NOTIFICATION
        orderNumber?.let { num ->
            Log.d("SupabaseOrderRepository", "Showing local notification for order #$num")
            NotificationHelper.showNewOrderNotification(applicationContext, num)
        }

        // existing callbacks for ViewModel / Toast
        callbacks.forEach { it(orderId, orderNumber) }

        Log.d("SupabaseOrderRepository", "Calling refresh() after realtime INSERT event")
        applicationScope.launch { refresh() }
    }
}
```

Now, whenever a realtime INSERT comes in (foreground or background, as long as the process is alive), a notification will be posted.

## 2. Fix the ringtone (notification sound) – **channel gotcha**

On Android 8+ the **notification channel controls sound**. Two critical gotchas:

1. Once a channel is created, its sound/vibration **cannot be changed** by code.
   If you created the channel earlier *without* sound, then added `setSound(...)` later, it will still be silent forever.

2. If the user turned notifications for that channel to “silent” in system settings, you **cannot override** it in code.

So to guarantee sound:

### 2.1. Use a **new** channel ID

Pick a fresh ID, e.g.:

```kotlin
object Constants {
    const val NOTIFICATION_CHANNEL_ID = "orders_channel_v2"   // NEW ID
    const val NOTIFICATION_CHANNEL_NAME = "Orders"
}
```

Update this ID everywhere:

* `NotificationHelper` (Builder + `createNotificationChannel`)
* OneSignal payload (`android_channel_id`)

### 2.2. Make sure the channel itself has sound

```kotlin

    if (Build.VERSION.SDK_INT >= Build.VERSION_CODES.O) {
```
